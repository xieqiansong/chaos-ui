# 初始化 Vue 3 + Vite + TypeScript + Pinia + Vue Router 项目

初始化这个技术栈最推荐的方式是使用 Vue 官方脚手架 `create-vue`，它基于 Vite 构建，支持在创建时直接勾选 TypeScript、Pinia 和 Vue Router，一次性完成所有集成配置，无需手动安装和连接各模块。

## 一、环境准备

确保本机已安装 **Node.js 18+**（推荐 20 LTS 或更高版本）。可以使用以下命令检查：

```bash
node -v
npm -v
```

如果尚未安装，建议通过 [nvm](https://github.com/nvm-sh/nvm) 或 Node.js 官网安装。

## 二、使用 create-vue 创建项目

在终端中执行官方脚手架命令：

```bash
npm create vue@latest
```

该命令会启动交互式配置向导。按以下选择完成技术栈配置：

```
✔ Project name: … my-vue-app
✔ Add TypeScript? … Yes
✔ Add JSX Support? … No
✔ Add Vue Router for Single Page Application development? … Yes
✔ Add Pinia for state management? … Yes
✔ Add Vitest for Unit Testing? … No（按需选择）
✔ Add an End-to-End Testing Solution? … No（按需选择）
✔ Add ESLint for code quality? … Yes
✔ Add Prettier for code formatting? … Yes
```

> **说明**：`npm create vue@latest` 是当前 Vue 官方推荐的脚手架方式，底层使用 Vite，相比旧的 Vue CLI（基于 webpack）具有更快的冷启动和热更新速度。

创建完成后，进入项目目录并安装依赖：

```bash
cd my-vue-app
npm install
```

启动开发服务器：

```bash
npm run dev
```

浏览器访问 `http://localhost:5173` 即可看到初始页面。

## 三、项目结构概览

脚手架生成的目录结构如下：

```
my-vue-app/
├── src/
│   ├── assets/              # 静态资源（CSS、图片等）
│   ├── components/          # 公共组件
│   ├── router/
│   │   └── index.ts         # Vue Router 配置
│   ├── stores/
│   │   └── counter.ts       # Pinia store 示例
│   ├── views/               # 页面级组件
│   ├── App.vue              # 根组件
│   └── main.ts              # 应用入口
├── public/                  # 纯静态资源（不经过 Vite 处理）
├── index.html
├── vite.config.ts           # Vite 配置
├── tsconfig.json            # TypeScript 配置
└── package.json
```

## 四、核心配置详解

### 4.1 入口文件 `src/main.ts`

脚手架生成后，`main.ts` 中已经自动注册了 Pinia 和 Vue Router，核心代码如下：

```typescript
import './assets/main.css'

import {createApp} from 'vue'
import {createPinia} from 'pinia'

import App from './App.vue'
import router from './router'

const app = createApp(App)

app.use(createPinia())
app.use(router)

app.mount('#app')
```

### 4.2 Vue Router 配置 `src/router/index.ts`

脚手架默认使用 `createWebHistory` 模式（HTML5 History 模式）。如果需要改为 Hash 模式，可将 `createWebHistory` 替换为 `createWebHashHistory`。路由配置使用
`RouteRecordRaw` 类型，这是 Vue Router 4 在 TypeScript 下的推荐类型：

```typescript
import {createRouter, createWebHistory} from 'vue-router'
import type {RouteRecordRaw} from 'vue-router'
import HomeView from '@/views/HomeView.vue'

const routes: RouteRecordRaw[] = [
    {
        path: '/',
        name: 'home',
        component: HomeView,
        meta: {
            title: '首页',
            requiresAuth: false,
        },
    },
    {
        path: '/about',
        name: 'about',
        // 路由懒加载
        component: () => import('@/views/AboutView.vue'),
        meta: {
            title: '关于',
            requiresAuth: false,
        },
    },
]

const router = createRouter({
    history: createWebHistory(import.meta.env.BASE_URL),
    routes,
})

// 全局前置守卫：设置页面标题
router.beforeEach((to, _from, next) => {
    document.title = (to.meta.title as string) || 'Vue App'
    next()
})

export default router
```

**扩展 `RouteMeta` 类型**：在 TypeScript 中，如果需要在 `meta` 字段使用自定义属性，建议在项目根目录或 `src/types/` 下创建一个 `.d.ts` 声明文件进行类型扩展：

```typescript
// src/types/router.d.ts
import 'vue-router'

declare module 'vue-router' {
    interface RouteMeta {
        title?: string
        requiresAuth?: boolean
        // 按需添加更多 meta 字段
    }
}
```

这样在路由配置中设置 `meta` 以及使用 `to.meta` 时都能获得完整的类型提示。

### 4.3 Pinia Store 配置 `src/stores/`

Pinia 官方推荐使用 **Setup 语法**（Composition API 风格）定义 store，因为它对 TypeScript 的类型推断支持最好，且无需 `this` 绑定。以下是一个典型的用户 store 示例：

```typescript
// src/stores/user.ts
import {ref, computed} from 'vue'
import {defineStore} from 'pinia'

interface User {
    id: number
    name: string
    age: number
}

export const useUserStore = defineStore('user', () => {
    // state：使用 ref 定义
    const user = ref<User | null>(null)
    const isLoggedIn = ref(false)

    // getters：使用 computed 定义
    const isAdult = computed(() => (user.value?.age ?? 0) >= 18)

    // actions：使用普通函数定义
    function setUser(payload: User) {
        user.value = payload
        isLoggedIn.value = true
    }

    function logout() {
        user.value = null
        isLoggedIn.value = false
    }

    return {
        user,
        isLoggedIn,
        isAdult,
        setUser,
        logout,
    }
})
```

在组件中使用时，TypeScript 会自动推断所有属性和方法的类型：

```vue

<script setup lang="ts">
  import {useUserStore} from '@/stores/user'

  const userStore = useUserStore()

  userStore.setUser({id: 1, name: 'Alice', age: 20})
  console.log(userStore.isAdult) // boolean
</script>
```

如果需要获取 store 的类型，可以使用 `ReturnType`：

```typescript
export type UserStore = ReturnType<typeof useUserStore>
```

## 五、关键配置提醒

**路径别名**：脚手架默认已在 `vite.config.ts` 和 `tsconfig.json` 中将 `@` 映射到 `src/` 目录，可以直接使用 `@/components/...` 和 `@/stores/...` 进行导入。

**TypeScript 严格模式**：确保 `tsconfig.json` 中 `strict: true`（脚手架默认已开启）。Pinia 需要 `strict` 或至少 `noImplicitThis` 才能正确推断 store 中 state 的类型。

**包管理器**：脚手架同时支持 npm、pnpm、yarn。如果团队使用 pnpm，建议在项目根目录添加 `.npmrc` 文件配置 `shamefully-hoist=true` 以避免某些依赖的提升问题。

**路由懒加载**：对于非首屏页面，统一使用 `() => import('@/views/XxxView.vue')` 进行懒加载，这是 Vue Router 4 的推荐实践。

## 六、后续建议

项目初始化完成后，可以按需添加以下能力：

- **HTTP 请求**：安装 `axios`，在 `src/utils/` 下封装请求拦截器和响应拦截器
- **自动导入**：使用 `unplugin-auto-import` 和 `unplugin-vue-components` 自动导入 Vue、Pinia、Vue Router 的 API 以及组件
- **代码规范**：如果创建时选择了 ESLint 和 Prettier，脚手架已生成对应配置，可直接运行 `npm run lint` 和 `npm run format`
- **环境变量**：在项目根目录创建 `.env` 和 `.env.production` 文件，以 `VITE_` 前缀定义环境变量，通过 `import.meta.env.VITE_XXX` 访问

通过以上步骤，你已获得一个完整的 Vue 3 + Vite + TypeScript + Pinia + Vue Router 项目骨架，可以直接开始业务开发。

# 集成组件

常用 UI 组件库与图表库的接入方式。两者均基于当前已就绪的 Vue 3 + Vite + TypeScript 技术栈。

## Element Plus

[Element Plus](https://element-plus.org/) 是 Vue 3 的桌面端组件库，提供表单、表格、弹窗等大量开箱即用组件。

### 安装

```bash
npm i element-plus @element-plus/icons-vue
```

- `element-plus`：组件库本体
- `@element-plus/icons-vue`：官方图标集合（按需使用）

### 方式一：全量引入（最简单，适合快速验证）

在 `src/main.ts` 中注册，所有组件与样式全局可用：

```typescript
import { createApp } from 'vue'
import ElementPlus from 'element-plus'
import 'element-plus/dist/index.css'
import App from './App.vue'

const app = createApp(App)
app.use(ElementPlus)
app.mount('#app')
```

> 全量引入会把整个组件库打进包里，**生产环境不推荐**，仅适合原型或后台管理系统这类对体积不敏感的场景。

### 方式二：按需自动导入（推荐，契合「自动导入」建议）

借助 `unplugin-auto-import` 和 `unplugin-vue-components`，在用到组件时才自动引入，且无需手写 `import`。同时与「六、后续建议」中的自动导入方案统一。

```bash
npm i -D unplugin-auto-import unplugin-vue-components
```

在 `vite.config.ts` 中增加插件：

```typescript
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueDevTools from 'vite-plugin-vue-devtools'
import AutoImport from 'unplugin-auto-import/vite'
import Components from 'unplugin-vue-components/vite'
import { ElementPlusResolver } from 'unplugin-vue-components/resolvers'
import { fileURLToPath, URL } from 'node:url'

export default defineConfig({
  plugins: [
    vue(),
    vueDevTools(),
    AutoImport({
      resolvers: [ElementPlusResolver()],
    }),
    Components({
      resolvers: [ElementPlusResolver()],
    }),
  ],
  resolve: {
    alias: {
      '@': fileURLToPath(new URL('./src', import.meta.url)),
    },
  },
})
```

配置后，模板里直接使用 `<el-button>`、`<el-table>` 等组件即可，无需 `import`；API 如 `ElMessage` 也会自动可用。插件会在项目根目录生成 `auto-imports.d.ts` 与 `components.d.ts` 供 TS 识别，请将这两个文件加入版本管理（已在 `.gitignore` 中默认不忽略，可直接提交）。

### 图标使用

```vue
<script setup lang="ts">
import { Search } from '@element-plus/icons-vue'
</script>

<template>
  <el-button :icon="Search">搜索</el-button>
</template>
```

## ECharts

[ECharts](https://echarts.apache.org/) 是功能强大的数据可视化图表库。在 Vue 3 中有两种常见接入方式：**直接使用 `echarts`** 或 **使用 `vue-echarts` 封装组件**。

### 安装

```bash
npm i echarts
# 若选择封装组件方案，再装：
npm i vue-echarts
```

### 方式一：直接使用 echarts（推荐，控制力强）

封装一个初始化图表的可组合函数 `src/composables/useChart.ts`：

```typescript
import { onBeforeUnmount, onMounted, ref, type Ref } from 'vue'
import * as echarts from 'echarts'

/**
 * 在指定容器上初始化并管理一个 ECharts 实例。
 * @param option 图表配置项（响应式变化时自动 setOption）
 */
export function useChart(option: Ref<echarts.EChartsOption>) {
  const el = ref<HTMLElement | null>(null)
  let chart: echarts.ECharts | null = null

  function resize() {
    chart?.resize()
  }

  onMounted(() => {
    if (!el.value) return
    chart = echarts.init(el.value)
    chart.setOption(option.value)
    window.addEventListener('resize', resize)
  })

  // option 变化时更新
  watchEffect(() => {
    chart?.setOption(option.value)
  })

  onBeforeUnmount(() => {
    window.removeEventListener('resize', resize)
    chart?.dispose()
    chart = null
  })

  return { el }
}
```

组件中使用：

```vue
<script setup lang="ts">
import { ref } from 'vue'
import type { EChartsOption } from 'echarts'
import { useChart } from '@/composables/useChart'

const option = ref<EChartsOption>({
  tooltip: {},
  xAxis: { type: 'category', data: ['Mon', 'Tue', 'Wed', 'Thu', 'Fri'] },
  yAxis: { type: 'value' },
  series: [{ type: 'bar', data: [120, 200, 150, 80, 70] }],
})

const { el } = useChart(option)
</script>

<template>
  <div ref="el" style="width: 100%; height: 360px"></div>
</template>
```

> 使用 `import * as echarts` 会引入完整包。若需极致体积，可按需引入：`import { init, use } from 'echarts/core'` 并 `use([BarChart, GridComponent, ...])`。

### 方式二：vue-echarts 组件（模板更简洁）

`vue-echarts` 把图表封装成 `<v-chart>` 组件，自动处理 resize 与销毁：

```vue
<script setup lang="ts">
import VChart from 'vue-echarts'
import { use } from 'echarts/core'
import { CanvasRenderer } from 'echarts/renderers'
import { BarChart } from 'echarts/charts'
import { GridComponent, TooltipComponent } from 'echarts/components'

use([CanvasRenderer, BarChart, GridComponent, TooltipComponent])

const option = { /* 同方式一 */ }
</script>

<template>
  <v-chart :option="option" autoresize style="width: 100%; height: 360px" />
</template>
```

> 方式二更契合 Vue 的声明式写法，但需手动 `use([...])` 注册所需模块；方式一用原生 `echarts` 更直接。两者按团队偏好选择即可。
